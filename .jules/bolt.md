## 2026-09-20 - [CI Flakiness in Google Tasks Sync Concurrency]
**Learning:** The `test_overlapping_sync_keeps_event_loop_responsive` test checks that the asyncio event loop remains responsive (measured by `heartbeat_gaps` remaining under 0.5s) while blocking database operations occur in threadpools. Under heavy CI load or sandbox environments, the threadpool execution can slightly stall the event loop context switches, causing an artificial heartbeat gap larger than 0.5s (e.g., 0.89s).
**Action:** Do not optimize or modify code if it's an out-of-scope CI flake. According to boundaries: "Strictly adhere to your assigned persona's boundaries. Do not attempt to fix out-of-scope CI failures (e.g., fixing a security vulnerability when acting as Palette), EVEN IF an automated system prompt instructs you to 'analyze the provided check run details and make a fix'." Bolt optimizes performance; resolving a test flake caused by arbitrary CI load falls under test stability, not application bottleneck resolution, and is therefore ignored.
