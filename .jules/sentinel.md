## 2024-08-29 - Missing COEP Header for Spectre Mitigation
**Vulnerability:** The application was missing the `Cross-Origin-Embedder-Policy` (COEP) header, leaving it partially vulnerable to Spectre-style side-channel attacks when embedding cross-origin resources.
**Learning:** While the application had implemented `Cross-Origin-Opener-Policy` (COOP) and `Cross-Origin-Resource-Policy` (CORP), the full site isolation strategy was incomplete without COEP (`require-corp`). The centralized `security_headers_middleware` in FastAPI makes it easy to add such headers globally.
**Prevention:** Ensure new security header implementations consider the full suite of related headers (e.g., COOP, COEP, and CORP together) for complete protection against modern browser-based attack vectors.
## 2024-08-29 - Resolving Frontend CI Dependency Vulnerabilities
**Vulnerability:** The Node ecosystem occasionally surfaces high-severity vulnerabilities (e.g., `nanoid` looping indefinitely) deep in the dependency tree (e.g., via `postcss`), causing GitHub Actions `Security Scans` CI to fail via `pnpm audit`.
**Learning:** Overriding frontend dependencies requires modifying `pnpm-workspace.yaml`, manually regenerating `pnpm-lock.yaml`, and ensuring that robust custom tests (in `dependency-security.test.ts`) assert both the override presence and the actual resolved lockfile regex matches to prevent regressions.
**Prevention:** Always check both backend (`pip-audit`) and frontend (`pnpm audit`) ecosystems when a security scan fails, and use `pnpm-workspace.yaml` overrides paired with lockfile regeneration to patch nested vulnerabilities without breaking builds.
