01 · proposed policy

Add one explicit default

Recommended location: Frontend Patterns, immediately after the dropdown audit rule. It belongs beside the other cross-feature UI conventions.

Current

No direct UI-description default

The policy covers friendly labels and dropdown values, but it does not tell contributors when supporting copy is unnecessary.

Proposed
UI descriptions: Do not add subtitles, helper text, or descriptive copy beneath headings, labels, cards, or settings by default. Prefer one concise, self-explanatory heading or label. Only add supporting copy when the user explicitly asks for it or when it is necessary to prevent misunderstanding or error, and never use it to restate the heading.

Wording is spacing-normalized from the request; meaning is unchanged.

02 · decision test

Three questions before adding copy

01

Does it add distinct information?

If it only paraphrases the heading or visible controls, remove it.

02

Does it prevent a real mistake?

Keep consequences, scope boundaries, validation behavior, and recovery guidance.

03

Can the heading carry the context?

When the target matters, name it in the title instead of adding a second line.
